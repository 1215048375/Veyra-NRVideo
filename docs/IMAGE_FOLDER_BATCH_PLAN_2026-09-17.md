# 全目录预渲染与参数无关缓存

用户要求增加全目录任务、进度条和新增图片增量处理，并明确缓存命中不受参数调整影响。本条取代此前 IMAGE_DISK_CACHE / IMAGE_PRERENDER 文档关于参数变化使缓存失效的规则。

缓存以原文件名、解码尺寸和原像素SHA256作为源身份，固定 rendered 后缀；不再将模型参数、SR目标、运行组件或程序构建放入身份。旧参数哈希命名的缓存仍按相同源前缀查找，优先最新的有效文件，仍验证输出尺寸与像素SHA256。调整参数不改变已缓存效果，缓存预览正常确认设置但不重新增强；新参数用于未缓存图片。连续20张队列也保留已完成项与进度。

新模型窗口 ImageBatchWindow 提供目录选择、开始/重新扫描、取消、原生进度条和完成/总数、新渲染、跳过、失败计数。每次开始重新枚举当前目录PNG/JPG/JPEG，忽略音视频和子目录（包括_cache）。EngineController的同一工作线程执行全目录任务，替换当前预览任务；只保留文件路径列表与当前一张输入/输出，不把整目录放进GPU队列。任务设置在开始时固定，局部保护区域按目录导航惯例清除。

逐张解码原图并确认已有缓存；命中不创建增强图、不改写缓存。缺失/损坏才经共享StillImageRenderer/EnhanceGraph或TiledImageProcessor处理与保存。GPU设备在首个未缓存项时创建，同一任务复用，结束释放。输入解码上限512MiB，与现有预渲染限制一致。再次扫描新增图片只增加未命中项目；没有自动目录监视。取消或切换其他任务在已有不可抢占步骤结束后退出，已保存结果保留，下次跳过。

验证：缓存参数无关身份、旧命名兼容、缺缓存修复、连续队列与D3D12缓存预览；全目录3张首次全渲染、开启NR参数后二次全部跳过（无NR运行组件也不会初始化）、新增第4张只渲染1张、取消；真实UI首次27张（超过20）全部生成、进度10000/10000，新增1张后二次新渲染1/跳过27且旧缓存mtime不变，坏JPG单独记失败。进度100%代表所有项已处理，失败仍单独显示。

本机成功GPU路径效果关闭；实际NR/SR成功Create/Evaluate未执行。已有运行组件与patched FFmpeg不变，无push或发布。具体命令、日志和最终包见WORKLOG。
