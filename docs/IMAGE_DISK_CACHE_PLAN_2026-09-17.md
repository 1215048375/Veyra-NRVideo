# 已渲染图片磁盘缓存与统一目录导航

用户授权：可选地保存已渲染图片到原图同目录的 `_cache`，下次读取结果而不重复增强，仍可原图/分屏对比；单张图片与目录浏览联通。

实现：图片菜单开关默认关闭，UiPreferences v5 保存并向后兼容。缓存源标识含原文件名、解码尺寸和像素 SHA256；效果标识含 NR/SR、模型、残差、保护区域、尺寸策略及组件/程序大小与时间戳。显示/音频/会话 revision 不改变图片内容，不参与效果身份。无损 PNG 与尺寸/像素 SHA256 记录采用临时文件后替换；不覆盖原图，失败只影响缓存。源码 Git 忽略 `_cache`。

普通图片输出完成后，启用开关才进行一次显式图片结果回读和保存；不改变视频实时/视频导出路径。读取缓存发生在 NGX 图初始化之前，复用已有大图结果浏览器（共享无增强 EnhanceGraph/VideoPresenter），保持完整结果用于保存。原图与增强图用同一归一化坐标比较，支持 SR 后不同尺寸，双线性取样。预览纹理上限4096每边，窗口缩放不重新增强。切换效果或禁用缓存回到正常处理；普通图设置变化重新检查缓存。GPU设备保留开关独立。

打开单张时发现父目录并选中对应项，刷新布局；原图列表、上一张/下一张、双击返回共用现有 ImageFolder。目录不递归，因此不会把 `_cache` 自动加入原图列表。直接浏览模式也能返回列表并转为手动选择。

验证：ImageRenderCacheTests 检查无损尺寸/像素、原图与设置变化、损坏修复、校验失败、写入失败，以及不同尺寸的原图/分屏采样。playlist.ps1 检查设置保存、列表、两种 AppShell 编译与620张缩略图。真实程序脚本检查从目录中间单张打开、前后翻图、双击返回、缓存重新打开及禁用；人工构造与原图不同的640×360缓存后，实际保存像素完全吻合。详见 WORKLOG 日志。

真实D3D12缓存测试在设置请求NR的情况下直接加载人工构造的缓存，验证零NR Evaluate、完整保存结果和另一套缓存参数切换。4097×4097大图也完成启用缓存、重开与保存检查（增强关闭）。这不代表本轮执行过NR模型生成；NR/SR/FG Create/Evaluate仍未执行。

边界：缓存命中仍需解码原图和PNG并建立显示资源；不保证零等待。缓存不自动限额或删除，PNG可能较大。组件替换按大小/时间戳失效，不是运行时哈希加载锁。真实大图NR耗时或用户素材的目视效果未验收。无新发布授权。最终本地目录：out/packages/Veyra-1.2.0-local-20260917-image-cache2。
