# 后续20张真正增强预渲染

用户指出原先CPU预解码没有解决增强耗时，明确要求预先执行增强。以本计划替换连续浏览中的解码进度含义；原图列表的手动选择模式仍不预渲染邻图。

图片菜单“连续浏览文件夹…（预渲染后20张）”启用队列和磁盘结果缓存。先完成当前图片，再在EngineController同一GPU工作线程、同一设备/队列上逐张处理后续最多20张。StillImageRenderer组装现有EnhanceGraph，普通图使用原图尺寸/相同ResolutionPlan及NR/SR/残差/保护参数，分块大图复用TiledImageProcessor。每张独立reset，不将不同图片当作时间连续帧；不新增NGX实现或第二套视频循环。

后台任务只在当前预览空闲处执行一次。切图、停止、设置变化取消后续工作，已提交的GPU计算和当前解码/写盘步骤有不可抢占边界。队列随ImageFolder顺序滑动；仍被需要的完成项保留，取消项可重试，失败不计入完成且不逐帧重试。设置变化清空旧进度；局部保护框沿现有翻图规则只用于当前图，未来图片清除区域。

输出必须完成处理并成功保存到原图旁 `_cache` 才计入完成数。所选NR/SR若未产生Evaluate计数，拒绝结果，禁止以原图或仅解码冒充增强。开启效果失败显示失败数量。效果全关可缓存基础GPU处理结果，但不宣称进行了NR/SR。增强结果内存缓存512MiB，按即将浏览的顺序优先保留；已选结果在更新窗口前固定持有，翻页命中跳过增强。超预算的已完成结果保留在磁盘，读取时仍可原图/分屏对比。原图预解码仍为独立512MiB上限。

当前UI显示“预渲染 完成/目标”，末尾0/0，失败单独标记；MINI显示分数。返回列表停止队列。关闭磁盘缓存转为手动模式并清空后台目标，避免将CPU解码数重新标为预渲染数。原CLI --image-folder-prefetch 兼容为新行为，推荐 --image-folder-prerender。

验证：PlaylistTests覆盖队列顺序、取消重试、窗口滑动、参数失效、失败不计数和末尾；ImageRenderCacheTests --gpu 在真实D3D12上完成20张未来图片处理与磁盘生成、内存命中和新末尾补齐。真实AppShell测试在首次翻页前检查21张PNG（当前加20张）、未处理后续第21张以外图片；快速翻至末尾0/0、关闭缓存退出模式、返回列表停止均通过。缺失本地NGX配置时两张任务均失败，进度0/2且当前缓存图继续显示。

本机没有获准的NR/SR运行组件，本轮未取得真实NR/SR成功Create/Evaluate及用户素材画质证据。GPU回归成功路径为效果全关；缺组件路径实际报ngx-local.json missing，不将失败测试当作NR成功。共享图调用已接入，最终需用户带原组件验证NR/SR实际效果和等待时间。单次后台图的资源初始化仍有成本，当前实现未声称跨图保留NR Feature。没有发布授权，保留旧包。
